# 怎么拿到 accessToken / refreshToken

## 先说结论（三句话，看完就能动手）

1. **不需要 WorkDaddy，也不需要任何第三方工具。** 只要两样：装过 WorkBuddy 客户端并**登录过**，电脑上有 **Node.js 18+**。仓库自带的 `get-token.cjs` 会把解密全做完，你不用懂原理。
2. **必须在你自己那台电脑上取**，不能在云服务器 / 云沙箱 / 容器里取 —— 那里没有你的登录态，翻多久都翻不出来。
3. 取完把令牌填进 `config.json`，然后把 `tokens.json` 删掉，就可以部署了。

> 为什么会有人以为要 WorkDaddy：早期版本确实借了它的脚本取密钥，现在已经把这段逻辑内联进 `get-token.cjs` 了，**只依赖 WorkBuddy 客户端本身**。

---

## 零基础五步（Windows，照着敲）

### 第 1 步：确认 Node 版本

`Win + R` → 输入 `powershell` → 回车 → 敲：

```powershell
node -v
```

- 显示 `v18.x` 或更高 → 继续；
- 提示「不是内部或外部命令」→ 去 <https://nodejs.org> 装 LTS 版，装完**关掉窗口重新开一个**再试。

### 第 2 步：把仓库弄到本地

```powershell
git clone https://github.com/interli3/workbuddy-cloud-worker.git
cd workbuddy-cloud-worker\cloud-worker
```

没装 git 就点仓库页面的 **Code → Download ZIP**，解压后进入 `workbuddy-cloud-worker\cloud-worker` 文件夹，在文件夹窗口的地址栏里输入 `powershell` 回车，再继续下一步。

### 第 3 步：取令牌

```powershell
node get-token.cjs
```

成功的样子：

```
✓ 解出 1 个账号 → C:\...\cloud-worker\tokens.json
  - 你的昵称：access 剩 30.0 天，refresh 剩 60.0 天，refreshToken 有
```

### 第 4 步：填进 config.json

```powershell
copy config.example.json config.json
node -e "const t=require('./tokens.json'),c=require('./config.json');c.accounts=t.map(x=>({name:x.name,uid:x.uid,accessToken:x.accessToken,refreshToken:x.refreshToken,expiresAt:x.expiresAt||0,refreshExpiresAt:x.refreshExpiresAt||0}));require('fs').writeFileSync('config.json',JSON.stringify(c,null,2));console.log('config.json 已填好')"
notepad config.json
```

在打开的记事本里把 `"access_key"` 改成**你自己随手编的一串字符**（这是管理端点的密码，别用默认值），保存关闭。

### 第 5 步：收尾

```powershell
del tokens.json
```

令牌已经复制进 `config.json` 了，`tokens.json` 留着只是多一份风险。**`config.json` 永远不要提交到 git、不要发群里、不要截图。**

## 出问题对照这张表

| 你看到 | 原因 | 怎么办 |
|---|---|---|
| `没找到 WorkBuddy 客户端` | 客户端装在非默认目录（D 盘、自定义目录） | `node get-token.cjs --exe "D:\你的路径\WorkBuddy\WorkBuddy.exe"`；找法：任务管理器 → 右键 WorkBuddy 进程 → 打开文件所在的位置 |
| `没找到登录态文件 workbuddy-desktop.info` | 从没登录过，或登录信息还没写盘 | 打开客户端确认能正常对话 → **完全退出** → 重新打开 → 再跑一次 |
| `取钥失败` / `exit=3` / `exit=4` | `--exe` 指错了程序，或客户端版本对不上 | 确认指到的是 `WorkBuddy.exe` 本身；把报错原文发出来 |
| `解出 0 个账号` | 登录态里没有可用账号 | 重启客户端重试；或用 `--info` 指向同目录下历史 `.info` 快照 |
| 只想先跑起来，不强求自动续期 | 没有 refresh 也能用 | `refreshToken` 留空即可，能跑 30 天，到期再取一次 |

## 详细版：为什么不能直接复制文件里的字符串

`config.json` 里最麻烦的一步就是这两个令牌。它们是**你自己的账号凭证**，只能从你自己的登录态里取，任何人（包括仓库作者）都没法替你生成。

下面三条路，**优先用第一条**。

> ⚠️ 令牌 = 你的账号。取了之后只放本地 `config.json`，不要发到群里、Issue、截图、公开仓库里。

> 🔴 **令牌必须在「装了客户端、且已登录」的那台电脑上取**。
> 云服务器 / 云沙箱 / 容器里没有客户端的登录态，在那里再怎么翻都翻不出令牌 —— 这是最常见的失败原因。
> 正确的顺序是：**本地取令牌 → 填进 config.json → 连 config.json 一起部署上去**。

## 路线 1（推荐）：跑 `get-token.cjs`，一次拿到 access + refresh

前提：这台电脑装了 WorkBuddy 客户端，并且**已经登录过**（能正常用 AI 对话）。

```bash
# Node 18+；脚本在 cloud-worker/ 目录下
node get-token.cjs
```

正常情况下你会看到：

```
· 客户端：C:\Users\you\AppData\Local\Programs\WorkBuddy\WorkBuddy.exe
· 登录态：C:\Users\you\AppData\Local\CodeBuddyExtension\Data\Public\auth\workbuddy-desktop.info
· 密钥：已取得（256 bit，只在内存里）

✓ 解出 1 个账号 → ...\tokens.json
  - 你的昵称：access 剩 30.0 天，refresh 剩 60.0 天，refreshToken 有
```

然后把它填进配置，二选一：

- **手动**：打开 `tokens.json`，把 `accessToken` / `refreshToken` / `expiresAt` / `refreshExpiresAt` 抄进 `config.json` 的 `accounts[0]`；
- **一条命令**（`tokens.json` 和 `config.json` 都在当前目录时）：

```bash
node -e "const t=require('./tokens.json'),c=require('./config.json');c.accounts=t.map(x=>({name:x.name,uid:x.uid,accessToken:x.accessToken,refreshToken:x.refreshToken,expiresAt:x.expiresAt||0,refreshExpiresAt:x.refreshExpiresAt||0}));require('fs').writeFileSync('config.json',JSON.stringify(c,null,2));console.log('config.json 已填好')"
```

填完就可以删掉 `tokens.json`。

### 它是怎么做到的

WorkBuddy 5.6 起把登录态做了**本地加密**，`workbuddy-desktop.info` 里看到的是这种信封：

```json
{ "auth": { "accessToken": { "$wbEncrypted": 1, "envelope": "eyJ2ZXJzaW9u..." } } }
```

所以你直接打开文件、或者 grep、或者在 LevelDB 里翻，**都只能拿到密文**——这是绝大多数人「拿不到令牌」的真正原因。

`get-token.cjs` 的做法是：

1. 用客户端自己的 Electron 运行时（`ELECTRON_RUN_AS_NODE=1`）执行一小段代码，调它内置的原生绑定 `electron_browser_workbuddy_storage.loggerGet()`，拿到本机 `atRestSecretKey`；
2. `sha256(atRestSecretKey)` → 32 字节 AES 密钥（只走进程管道，不落盘）；
3. 用这把钥匙按 `WB-AAD` 的 AAD 拼法解 AES-256-GCM，得到明文令牌。

全程在本机完成，不联网、不上传。客户端是 5.6 之前的版本（令牌本来就是明文）时，脚本也会直接读出来。

## 路线 2（兜底）：只要 access，够跑 30 天

`server.js` 对 `refreshToken` 是**可选**的：没有 refresh 也能正常签到、跑猫猫、做成长任务，只是 **access 到期（30 天）后不会自动续期**，到时候重取一次即可。

拿 access 的办法：客户端登录后开 DevTools（或在网页版登录），任意一次发给 `www.workbuddy.cn` 的请求里，请求头都有：

```
Authorization: Bearer eyJhbGciOi...（这就是 accessToken）
```

把它填进 `config.json` 的 `accessToken`，`refreshToken` 留空字符串，`expiresAt` 填 `0` 也可以。

---

## 路线 3：只有 refresh，换一对新的

官方刷新接口（`refresh` 放在**请求头**里，不在 body）：

```bash
curl -X POST "https://www.workbuddy.cn/v2/plugin/auth/token/refresh" \
     -H "X-Refresh-Token: <你的 refreshToken>"
```

返回 `code=0` 时，里面有新的 access **和轮换后的新 refresh**。

🔴 **每次刷新都会作废旧的 refresh。** 所以：

- 要么让本服务（云端）当唯一的「链主」，你别在别处再刷同一个 refresh；
- 要么你自己刷完，把**新的那对**都填回 `config.json`，别留旧的。

---

## 三条红线

1. `config.json` / `tokens.json` **永远不进 git**（仓库 `.gitignore` 已忽略，自己 fork 后别删这两行）。
2. 令牌等于账号：泄露 = 别人可以用你的账号跑任务、扣你的积分。
3. 别在公开 Issue 里贴令牌片段（包括前 20 个字符），要贴就贴报错信息。
